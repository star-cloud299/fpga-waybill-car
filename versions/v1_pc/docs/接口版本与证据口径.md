# 单机共用的接口版本与证据口径

版本 single-pc-v3，2026-10-23。

## 唯一正式业务接口

以 `official_v2/protocol.py`、`official_v2/uart_official_v2_top.sv` 和团队 `design_spec.pdf` 的V2为准。所有新的GUI、批量实验都复用同一协议实现，不增设另一套帧头。模式1..5、RAW8，最大已验收尺寸192×96。

B算法核采用 ready/valid 和裁剪后坐标，与设计PDF最初的无ready/原图坐标不同。本轮保留已在正式V2实板跑通的实现，不擅自替换为每拍一像素版本。新客户端依据响应 offset=0/1/7 映射原图区域。

| 项目 | PDF初始契约 | 已上板实现及本轮选择 |
|---|---|---|
| 输入时序 | valid，无ready，目标1像素/周期 | ready/valid；窗口核约2周期/像素 |
| 输出坐标 | 原图中心坐标 | B核裁后坐标；正式响应携带offset映射 |
| 灰度 | `(77R+150G+29B+128)>>8` | 保持正式B核和C模型中的+128舍入 |
| 整数均值 | floor(sum/9)或floor(sum/225) | 保持一致 |
| 偏置判定 | 9位center+C >= mean为白 | 保持一致 |
| 模式6/BIT1 | 条件增强 | 正式客户端不发送 |
| 最大尺寸 | 256×128目标 | 正式bit仅192×96；核256测试不等于板级验收 |

A/B/C同机只需在此版本统一记录签收，不需要互相打包复制三份工程。单机干净目录复现仍应保留，角色分工不取消复核责任。

## 四种证据不能混用

| 标记 | 来源 | 可得结论 |
|---|---|---|
| `pc_reference_only` | 新PC模型、合成测试图 | 离线算法/解码结果；没有FPGA像素差异和硬件周期 |
| `RTL_simulation` | Icarus运行真实RTL | 仿真范围内数学正确性、握手、错误恢复；不是实板测试 |
| `revalidated_uploaded_board_records` | 上传包中的原始硬件回包 | 旧回包的CRC/哈希/像素复核；不是本轮新跑板 |
| `board_current_run` | 用户明确选COM口、本次实际回包 | 本次实板CRC、像素及耗时；仍需记录实际bitstream来源 |

离线记录的 mismatch_count、processing_cycles、round_trip_s 为null。没有真实回包时不生成response.bin、fpga_result.png、diff.png。真实尝试失败则标为board_attempt_failed，并尽可能保留收到的原始字节。

`processing_cycles`是正式RTL自己回传的首像素到末结果的周期字段。它包含馈送停顿，不能等同于独立纯算法吞吐，也不能替代PC记录的UART往返时间。

## 参数和测试集

dataset_lock.json锁定清单与数据字节；frozen_profile.json锁定选参所用的12张tuning ID、完整候选网格、候选结果、软件版本和算法源文件哈希。调参函数不读取18张test的退化RGB565。

候选同分时按事先声明的顺序选择，默认参数优先。仅当模式5在调参集精确识别数严格高于模式4，才将其设为暂定默认，最终还要看独立测试和实板。

解码只限Code128，不针对某个模式单独增加锐化、旋转或阈值。多个不同解码文本也不当作正确。期望文本是字符串，保留前导零。

黑色为正类。precision/recall/F1/IoU的分母为0时使用null/CSV空单元格，不当作1。灰度模式不计算二值前景指标。相机照片没有可信配准真值时只做解码，不生成像素指标。

## 尚未实测的项目

本轮没有接入用户电脑的UART、JTAG或摄像头，也没有运行Vivado。旧正式报告的WNS/资源仍属于上传基线。新增停止位等错误场景属于仿真，不能据此关闭“实板停止位错误注入”的待办。
