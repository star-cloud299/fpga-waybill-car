# 基础工程 v5：先看这里

这是可独立解压使用的完整工程，不是给旧工程覆盖文件的补丁。基础默认模式为15x15，正式验收覆盖模式1至4；模式5和实拍自动取图继续保留为可选扩展。已上传的数据和原有.bit不会因运行自检而重写。

## 打开方式

1. 解压到新的英文路径，例如 D:\fpga_jingsai\waybill_foundation_v5。不要覆盖目前已经跑通的旧目录。
2. 依赖已经安装时直接双击 foundation_menu.bat；菜单1为基础界面，菜单2为此前实拍自动版。
3. 新环境双击 setup_environment.bat，安装 requirements.lock.txt 并运行自检。任何一步失败会停止提示。
4. 基础界面会载入固定示例和期望文本，无需手填ROI；手动读取其他图片时仍可框选。实拍自动定位请用菜单2。
5. 所有新运行保存到本工程 runs 下。GUI每次额外保存 modes.csv，不需手抄五模式结果。

## 菜单能做什么

- 1/2：基础界面/扩展界面。
- 3：锁定环境、算法和数据校验；软件测试；历史100帧与10帧扫模式记录复核。不连接串口。
- 4/5：独立复核正式150帧和实拍记录的请求、响应CRC、像素、解码与文件哈希。不连接串口。
- 6：Icarus RTL回归，覆盖算法核、五模式UART和异常恢复。需要iverilog、vvp在PATH。
- 7：朴素K×K求和与现有滑动统计的对比仿真，含背压、换行和换尺寸。
- 8：调用Vivado构建当前正式板级设计，输出新builds目录，不自动下载，不写Flash。
- 9：调用Vivado对两个窗口结构做同器件/同50MHz/同端口/同参数的OOC资源和时序对比，不改现用.bit。

你此前的实板结果已纳入，这里不要求再拍图片或重新做整批实验。stability_100_frames.bat是后续改RTL后可用的验收入口：明确输入COM口后才打开一次串口并连续发送100帧64x64图像；它是链路正确性测试，不是识别率测试。模拟测试日志中的TEST_ONLY和模拟会话不是硬件实测。

## 当前证据

- 原正式150帧：2517480输出像素与软件一致。
- 新增实拍15帧：251748输出像素与软件一致；同照片PC记录另有15帧。
- 本轮RTL回归：30帧299920算法核像素、7帧正式UART、20种恢复场景。
- 新增窗口对比：3x3和15x15共6帧1112输出，两种结构与直接数学计算一致。
- 本轮软件测试15项；GUI worker另有10项无显示环境检查。Windows窗口实点和本轮新Vivado/新实板未在这里运行。

原bit资源：LUT1820、FF902、BRAM26.5、DSP2；50MHz约束下WNS+2.334ns、TNS0。它们是同一原bit的历史报告，不是新模块的实测资源。OOC比较基线是本轮为比较明确编写的朴素结构，不宣称是历史优化前版本；未跑Vivado前不能填写LUT节省比例或加速倍数。UART往返约4.49秒与回传周期字段约0.737毫秒不是同一指标，不能混用。

## 尚未关闭的原方案目标

- 正式板级最大192x96；256x128仅完成算法核仿真，原方案的板级最大支持目标仍未关闭。
- 当前窗口核约2周期/像素；不能写为1像素/周期。
- 正式UART仍为五模式RAW8；模式6、裕量图、BIT1、重传不在本基础版启用。
- 停止位错误恢复已有引脚级仿真；实板停止位错误注入未补测。
- 两种结构的Vivado资源/时序比较、全套工程在另一台Windows从零复现，需要对应本地工具执行，未标完成。

这次范围是工程与可执行验收入口，不包含新实验报告、PPT或演示视频。需求追踪.csv逐项对照原方案，profiles/foundation_contract.json定义真实边界；后期创新从extensions和benchmark扩展，原正式接口和证据不改写。
