# 实拍自动定位 v4.1 安装与使用

1. 关闭正在运行的上位机。将本压缩包完整解压，不要在压缩包内运行。
2. 双击 apply_fix.bat。若提示路径，填写包含 run.py 和 host 文件夹的工程目录，例如：
   D:\fpga_jingsai\waybill_single_pc_v3\single_pc_v3
3. 安装成功后，用原工程 start_gui.bat 重开。窗口标题应包含“实拍自动定位 v4.1”。
4. 保持“实拍自动定位（解码辅助选框）”“使用已冻结参数”和“依次比较五模式”勾选。
5. 直接读取实拍原图，等待自动选框，不用输入ROI。按纸面号码填写期望文本，保留前导零。
6. 点击开始处理并保存，先PC参考，再切换FPGA实测。每种模式仍使用同一个选框和输入。
7. FPGA实测核对差异像素为0；识别失败按真实情况保留。

## 已验证的范围

在本次上传的08.jpg、07.jpg、04.jpg上，PC软件复核模式1、2、4、5均得到000026000003，模式3仍未解码。没有运行新的真实开发板测试，也没有可用图形显示环境进行窗口实点测试；界面回调和工作线程用模拟对象检查。请在Windows实测复核。

## 自动选框做了什么

先依靠纵向重复边缘定位单个横向条码，再尝试固定32种留白/高度组合，使用冻结参数的软件参考输出及原解码器选择可解码模式共识最多的一个框。选框从不读取期望文本，不逐模式使用不同输入，也不会修改精确匹配结果。选中后五模式共享同一个192x96 RGB565输入；开发板继续计算原有模式。

这属于新的“解码辅助实拍流程”，不是纯几何定位。roi_geometry.json记录所有候选、选中依据和版本。它会用到各模式的预解码信息，不能作为与旧固定ROI流程公平对比的正式准确率。此前批量数据、冻结参数和.bit均保持不变。新图片的泛化能力还需在预先固定的新样本上检验。

## 为什么模式3还会失败

3x3邻域可能完全位于黑条内部，此时中心和均值接近，加上偏置后黑条内部容易被判白。自动取图能改善采样，但不能保证修复算法本身。当前补丁未修改RTL；若要改变该算法，需同步修改软件与RTL、重新仿真并生成.bit后再验证，不能只更改显示文字。

## 范围与回退

适用于一张图只有一个、近似水平的完整Code128条码。严重倾斜、遮挡、反光或多个条码会影响定位；失败时会提示，停止自动处理，可关闭自动定位后手动框选。自动选框不是保证识别成功。

手动框选或应用精确坐标会关闭自动定位；重新勾选即可恢复。载入标准示例会关闭自动定位，维持原示例坐标。新图片/新ROI会清除旧结果，避免误认为上次结果来自新输入。

安装器校验文件版本，备份到原工程backups/photo_auto_v4_时间目录；不覆盖算法、参数、历史runs或bit文件。回退时关闭界面，将该备份host下的文件复制回原host；若备份中没有auto_roi.py，则可以删除新host/auto_roi.py。无需重装依赖，无需重新烧录开发板。
